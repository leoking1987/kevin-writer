# Kevin 原文对照与改写

## 使用参考组

先读 [样本索引](index.md)。首次使用本技能完整读取五篇全文，建立对作者真实说话的整体认识；同一会话已读过时，回到与当前题材最接近的全文，而不是凭记忆套“理性、专业”的人设标签。

写前选出至少两段经确认的 Kevin 本人连续发言作为锚点，覆盖当前稿最需要的功能，例如数据解释、区域比较、现场判断或收口。记录视频 ID、段落起句及为什么适用。不要把 Marie 的追问、评价和生活体验当 Kevin 的口吻。双人对话的轮次不机械移植到独白稿。

五篇都是长期累计播放较高的样本，题材与年代并不相同。它们提供表达证据，无法证明某一句式带来了播放；不要求新稿复刻原视频的时长、开头寒暄、题材或咨询名额。

## 写后必须实际对照

先按根目录 SKILL.md 的观众得失规则复核选题、开场与关键句，再对照本人表达。原文锚点校准声音，不能代替本题的利益关系；平稳解说样本不能成为删除有依据的情绪或生活后果的理由。只有措辞像本人、却说不清观众获得或失去什么，仍须回到切口与证据重写。

对照用来校准本人的解释方法与语气，不把某一篇旧稿的情绪强度当作上限。按 `SKILL.md` 的情绪表达要求，检查关键得失是否让观众有感受；有当前事实支持的担心、不甘、欣赏和释然应保留，不为了贴近平稳的数据解说全部删掉。

逐段检查以下问题，把生成段落与适用的本人原文并排读：

| 看什么 | 需要比较的实际内容 |
| --- | --- |
| 句子如何接续 | 原文怎样把原因、比较、条件和结果接在一起；生成稿是否只剩连续口号、碎句或公文连接词 |
| 信息怎样展开 | 原文如何定义口径、介绍来源、解释数字或比较地区；新稿是否只宣告结论 |
| 设问如何使用 | 问题是否来自观众当前需要知道的内容；问后是否真给了回答 |
| 判断怎样成立 | 是否区分数据、推断与成立条件；是否用抽象对照掩盖未解释的机制 |
| 作者怎样出现 | 是否通过具体判断和处理办法表现专业；是否硬造个人经历或堆头衔 |
| 如何收口 | 是否顺着本期问题给建议或互动；是否突然开始无关营销 |

每个主要内容段落都要有适用的原文依据，可重复使用同一锚点。不要计算机械的用词相似度，也不要为了贴近原文复制旧数字、原事件、客户经历和时代话术。新题材在五篇中没有直接对应时，借用可确认的解释方法，并注明没有同体裁样本；不能声称已验证该体裁的本人风格。

## 改写闭环

内部记录至少保留：`成稿段落 → 原文 ID 与起句 → 具体偏差 → 改后段落 → 复核结果`。

遇到偏差，实际重写该段，再对照同一原文复核。整篇朗读一次检查衔接。全部关键偏差修正后才交稿；只有评价、评分或“符合风格”的声明不算完成。

后续若再做口语化、压缩时长或套其他结构，交付前对最终版本重新对照；不能让中间稿通过后，最终稿又换成另一位创作者的口吻。

无依据的“不是 X，而是 Y”“X 不代表 Y”“X 不等于 Y”要回到具体事实、原因和结果重写；真实必要的否定与纠偏可以保留。反常识须有确实存在的预期、经核实的相反结果和差异机制，不能把常见提醒包装成反常识。

用户指定“您”等新的团队语言要求时照常执行，不为了模仿早期视频退回旧称呼。原始转写保留识别状态，学习时纠正有证据的错词、黏连和冗余，不能照抄识别错误。风格始终受当前事实、品牌定位和隐私边界约束。

默认只交成稿；对照记录留在内部。用户要求审核或说明修改依据时，展示具体差异及修改，不输出空泛评分。
